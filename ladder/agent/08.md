# 8 · Forgetting on purpose

**The idea.** A model can only read so many tokens at once (its *context
window*), and every token costs money on every call. A long run keeps
piling up tool results until it doesn't fit. So you **forget**, carefully.
Some messages must never go: without the system prompt the model forgets
its tools, without the task it forgets its job. The newest message is the
one it is about to act on. Everything in between is fair game, oldest first.

A group chat on a small phone, the same rule:

```python
chat = ["PINNED: party saturday", "hi", "who brings cake?", "me!", "cool"]
def size(msgs):
    total = 0
    for m in msgs:
        total += len(m)
    return total

limit = 30                           # characters the screen fits
i = 1                                # 0 is pinned, never touched
while size(chat) > limit and i < len(chat) - 1:
    chat[i] = "..."                  # oldest first, the newest stays
    i += 1
print(chat)
```

Replacing with a short placeholder (rather than deleting) keeps the
turn-taking visible to the model. Real agents often ask the model to write
a summary instead; a placeholder is the honest first version.
