# 1 · A drawer of tools

**The idea.** A language model can only write text. It cannot open a file
or add two numbers for real. An **agent** is a small program around the
model: the model *writes* "please run tool X with these arguments", your
code runs it, and hands the result back. So first the agent needs a drawer
of tools it is allowed to run.

In Python a function is a value, like a number. You can store it in a dict
without calling it (no brackets), and call it later:

```python
def double(x):
    return x * 2

buttons = {}
buttons["double"] = double       # stored, not called
print(buttons["double"](4))      # 8: look it up, then call it

parts = ["milk", "eggs", "bread"]
print("\n".join(parts))          # one string, one item per line
```

The model also needs to *know* which tools exist. It can't see your code,
only text, so you describe each tool in words.

**Your turn.** New file `agent.py`:
- `register(name, fn, description)` stores a tool (a dict keyed by name is
  perfect). Registering the same name again replaces it
- `tools_prompt()` returns one string with a line `name: description` per
  tool, in the order they were registered, joined with `"\n"`

**Checked:** two tools listed in order; re-registering `add` replaces its
line instead of adding a second one.
