# 3 · The loop

**The idea.** An agent is one loop: *model → tool call → result → model*,
until the model says it's done. Chat APIs remember nothing, so each time
you send the **whole conversation**: a list of messages, each a dict
`{"role": ..., "content": <text>}`:

- `"system"`: the rules and the tool list (always first)
- `"user"`: the task
- `"assistant"`: what the model said
- `"tool"`: what a tool returned

A support-desk log, to show the shape:

```python
import json

log = [{"role": "system", "content": "Be kind."},
       {"role": "user", "content": "My order is late"}]
reply = {"ticket": 42, "status": "open"}
log.append({"role": "assistant", "content": json.dumps(reply)})
print(log[-1]["content"])        # {"ticket": 42, "status": "open"}  (a dict turned into text)
```

There is no real model here. Tests hand `run` a function `model` that
takes the messages list and returns a dict: `{"tool": name, "args": {...}}`
to call a tool, or `{"final": text}` when it's done.

**Your turn.** `run(task, model)`:
- starts with 2 messages: `system` (your instructions, containing
  `tools_prompt()`) and `user` (the task)
- loop: call `model(messages)`; add its reply as an `assistant` message
  (content must be text: use `json.dumps`); on `final`, return that text;
  on `tool`, run it with `call_tool` (missing `args` = `{}`) and add the
  result as a `tool` message

**Checked:** the exact messages the model receives on each call; tool errors
reach the model instead of ending the run; one call when it answers at once.
