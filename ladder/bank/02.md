# 2 · Guard clauses: say no early

**The idea.** Taking money out can go wrong in several ways. Beginners
nest `if`s until the real work sits five levels deep. Pros write **guard
clauses**: check each way it can fail at the top, `return` right away, and
let the happy path run flat at the bottom.

```python
def board(passengers, flight, name):
    if flight not in passengers:          # guard 1
        return None
    if name in passengers[flight]:        # guard 2
        return None
    if len(passengers[flight]) >= 180:    # guard 3
        return None
    passengers[flight].append(name)       # happy path, not indented
    return len(passengers[flight])
```

Read it top to bottom: every line either quits or moves on. Crucially, the
guards come BEFORE any change, so a failed call leaves nothing half done.
