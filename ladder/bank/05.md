# 5 · A list of records, and searching it

**The idea.** A balance tells you *now*. A bank must also answer *"what
happened, and what was the balance last Tuesday?"* The answer: every change
appends a **record** to a list, and questions about the past are answered
by walking that list.

A record here is a small tuple `(timestamp, change)`. Store the *change*
(+500, -200), not the new balance: changes are easy to add up.

```python
steps = []                               # a fitness tracker
steps.append((7, 3000))                  # at time 7, +3000 steps
steps.append((12, 4500))
steps.append((20, 1000))

def steps_by(time):
    total = 0
    for when, amount in steps:           # unpack each tuple into two names
        if when <= time:
            total += amount
    return total

print(steps_by(12))                      # 7500: the record AT 12 counts
```

One place, many callers: deposit, withdraw and transfer all change money.
If each appends its own record, one day you forget one. Put "change the
balance AND write the record" into one helper, `_change(ts, id, delta)`,
and make every money move go through it.
