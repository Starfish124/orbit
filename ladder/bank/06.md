# 6 · Things that happen later

**The idea.** A scheduled payment is an event in the future. There is no
background thread and no clock: time only moves when someone calls a
method with a new `ts`. So the rule is: **at the top of every method,
first run everything that has become due**, then do the method's own work.
One helper, `_process(ts)`, called as the first line everywhere.

A reminder app, same pattern:

```python
class Reminders:
    def __init__(self):
        self.pending = []                     # each one is a small dict
        self.sent = []

    def _process(self, ts):
        due = [r for r in self.pending if r["at"] <= ts]
        due.sort(key=lambda r: (r["at"], r["number"]))    # earliest first
        for r in due:
            self.pending.remove(r)
            self.sent.append(r["text"])

    def add(self, ts, text, delay):
        self._process(ts)                     # first line, always
        self.pending.append({"at": ts + delay, "number": len(self.sent) + len(self.pending), "text": text})
```

`[r for r in ... if ...]` is a **list comprehension**: a filtered copy.
Never remove from a list while looping over *that same* list; loop over the
copy (`due`) instead.

- several due at once: earliest due first; same due time: scheduled first
- `cancel_payment(ts, account_id, payment_id)` → `True` if that payment is
