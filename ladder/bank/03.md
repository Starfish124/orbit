# 3 · Money is never a float

**The idea.** Try this in any Python:

```python
print(0.1 + 0.2)            # 0.30000000000000004
print(0.1 + 0.2 == 0.3)     # False
```

Floats store numbers in binary, and 0.1 has no exact binary form, just as
1/3 has no exact decimal form. For a physics sim that tiny error is fine.
For money it is a bug: add enough of them and a cent appears or vanishes.
Banks store **whole cents as ints**: €12.34 is `1234`. Ints are exact.

So the bank must refuse anything that isn't a positive int. Check the type
with `isinstance(value, int)`, and refuse by raising:

```python
def set_age(age):
    if not isinstance(age, int) or age < 0:
        raise ValueError("age must be a whole number, 0 or more")
    return age
```

A bad *amount* is the caller's programming mistake, so it raises. A missing
account is normal business, so it still returns `None`. Check the amount
first, before looking at accounts.

When three methods need the same check, write it once as a helper method
(a name starting with `_`, like `_check_amount`) and call it from each.

**Your turn.** `deposit`, `withdraw` and `transfer` raise `ValueError` when
`amount` is not an int, or is 0 or less. That includes floats like `10.5`
and text like `"10"`. Everything else from stages 1-2 stays the same.

**Checked:** 0, -5, 10.5 and "10" all raise on all three methods (even for
unknown accounts), nothing changes after a rejection, normal amounts work.
