# 1 · A bank is a dictionary with rules

**The idea.** This unit is the banking task that AI labs hand out in coding
interviews. It arrives in stages, and each stage adds a rule. Underneath it
all is something you already know: a dict from account id to balance,
inside a class.

New here: every method takes a **timestamp** `ts` first. It is just an int
saying *when* the call happens (1, 2, 3...). No clock needed: the caller
tells you the time. For now you can ignore it; stage 5 and 6 use it.

A worked example on a different topic, a library:

```python
class Library:
    def __init__(self):
        self.copies = {}                  # title -> how many copies

    def add_title(self, ts, title):
        if title in self.copies:
            return False                  # already there: say so, change nothing
        self.copies[title] = 0
        return True

    def stock(self, ts, title, n):
        if title not in self.copies:
            return None                   # None = "no such thing"
        self.copies[title] += n
        return self.copies[title]
```

**Your turn.** Write `class Bank` with:
- `create_account(ts, account_id)` → `True`, or `False` if that id exists
  (and then change nothing)
- `deposit(ts, account_id, amount)` → the new balance, or `None` for an
  unknown account
- `get_balance(ts, account_id)` → the balance, or `None` if unknown

A new account starts at 0.

**Checked:** True/False on create, re-creating never resets money,
deposit returns the new balance, unknown → None, two banks are separate.
