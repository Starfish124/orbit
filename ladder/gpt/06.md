# 6 · Your first language model: one letter predicts the next

**The idea.** A *bigram* model guesses the next character from only the
previous one. Its knowledge is a table: row = previous character, column =
next character, entry = a logit (a learnable Value). "." marks the start
and end of a name, so "ava" is the pairs `.a av va a.`.

The old-fashioned way is counting. Same idea, other topic: weather.

```python
days = ["sun", "sun", "rain", "sun", "rain", "rain"]
counts = {}
for a, b in zip(days, days[1:]):          # neighbouring pairs
    counts[(a, b)] = counts.get((a, b), 0) + 1
print(counts)    # {('sun','sun'): 1, ('sun','rain'): 2, ('rain','sun'): 1, ('rain','rain'): 1}
```

You will **learn** the table with gradient descent instead: the same
machinery then scales to a GPT, where counting can't.

*Sampling* rolls a weighted die: `rng.choices(range(n), weights=probs)[0]`.
*Temperature* divides the logits before softmax: below 1 sharpens (0.01 ≈
always the top choice), above 1 flattens.

A dict built from a list in one line (a *comprehension*):
`{ch: i for i, ch in enumerate(vocab)}`.

**Your turn.** `Bigram(words, rng)`:
- `.vocab` = `"."` then the sorted distinct letters; `.stoi` = letter → index
- `.table` = V rows of V Values from `rng.uniform(-0.1, 0.1)`; `parameters()`
- `loss(words)`: mean `cross_entropy(table[prev], next)` over every pair of
  every `"." + word + "."`
- `train(words, steps, lr)`: gradient descent, returns losses like `fit`
- `sample(rng, temperature=1.0, max_len=20)`: start at "."; pick the next
  letter from the softmax of every logit divided by `temperature`; stop at "." (not included) or
  after `max_len` letters. `temperature <= 0` → `ValueError`
