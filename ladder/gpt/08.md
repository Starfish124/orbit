# 8 · A tiny GPT

**The idea.** A GPT is the bigram's table plus attention plus a little
thinking, stacked:

1. token `i` at position `t` becomes `wte[i] + wpe[t]` (element by element):
   a learned vector for *what* it is plus one for *where* it is (*embeddings*)
2. `x = x + attention(x)`: gather from the past
3. `x = x + fc2(tanh(fc1(x)))`: each position thinks alone (the *MLP*)
4. `logits = lm_head(x)`: a score per token for the next one

The `x = x + ...` is a *residual connection*: each block only adds a
correction, so the original signal (and its gradient) always has a straight
road through. Other topic: editing a draft.

```python
draft = "the plan"
final = draft + ", with dates"       # adds to it, never throws it away
```

The model only knows `block_size` positions. To keep generating past that,
feed it just the tail: `tokens[-block_size:]`.

**Your turn.** `GPT(vocab_size, block_size, n_embd, rng)`:
- create in this order: `.wte` (vocab_size rows of n_embd Values) and
  `.wpe` (block_size rows) from `rng.uniform(-1, 1)`, `.attn =
  Attention(n_embd, rng)`, `.fc1 = Linear(n_embd, 4 * n_embd, rng)`,
  `.fc2 = Linear(4 * n_embd, n_embd, rng)`, `.lm_head = Linear(n_embd,
  vocab_size, rng)`; `parameters()` = all of them
- `model(tokens)` → one list of logits per position; more than
  `block_size` tokens → `ValueError`
- `loss(tokens)`: mean cross-entropy of each position predicting the next
  token; `train(tokens, steps, lr)` returns losses like before
- `generate(tokens, n, rng, temperature=1.0)`: prompt + `n` new tokens,
  each sampled from the last position's logits
