# 4 · The web is broken

**The idea.** Real pages time out, 404, reset the connection. One bad page
must not kill the crawl. `try` / `except` catches an error so the program
keeps going, and `as e` gives you the error itself to keep:

```python
bad = {}
for text in ["12", "x7", "40"]:
    try:
        n = int(text)
    except ValueError as e:
        bad[text] = e          # remember what went wrong, move on
        continue
    print(n * 2)
print(bad)                     # {'x7': ValueError("invalid literal ...")}
```

Some errors are temporary, so try again a few times. `for attempt in
range(retries + 1)` gives one first try plus `retries` more; `return`
inside the loop leaves as soon as one works, and after the loop you
`raise` the last error again.

Trap: a default of `errors={}` in the `def` line is created **once** and
shared by every call, so errors from one crawl leak into the next. Use
`errors=None` and only write to it when the caller passed a dict.

**Your turn.** `crawl(start, fetch, max_depth=None, errors=None, retries=0)`:
- if `fetch` raises (any `Exception`), try up to `retries` more times
- a page that still fails: keep crawling; if `errors` is a dict, store
  `errors[url] = the exception`
- a failed page still counts as found (something links to it); its own
  links are simply unknown

**Checked:** a 404 and a flaky page don't crash it; errors holds the
exceptions; `retries=2` means 3 tries and rescues a page that fails twice.
