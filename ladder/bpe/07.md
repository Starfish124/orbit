# 7 · Special tokens

**The idea.** Models need markers that are *not* text, like
`"<|endoftext|>"` between two documents. It must become ONE id, never be
split or merged, even though it's made of ordinary characters.

So before the normal encoding, cut the text on the special strings.
`re.split` with the pattern in `( )` keeps the pieces it cut on:

```python
import re
print(re.split("(;|, )", "a;b, c"))   # ['a', ';', 'b', ', ', 'c']
```

Special tokens are full of regex symbols: `|` means "or". `re.escape(s)`
makes a string match only itself: `re.escape("<|x|>")` is `'<\\|x\\|>'`.
Build the pattern as `"(" + "|".join(escaped_strings) + ")"`.

Decoding is easy if the special token's bytes also go into `vocab`.

**Your turn.** In `Tokenizer`:
- `self.special = {}` (string -> id)
- `add_special(text, id)`: register it; if `id` is already in `vocab`,
  raise `ValueError`. Keep specials in `vocab` even after re-training.
- `encode`: split on specials; a special piece becomes its id, everything
  else is encoded as in stage 6. With no specials, encode as before.
- `decode` turns the id back into the string

**Checked:** `"ab<|endoftext|> ab"` is `[256, 1000, 257]`, two specials in a
row, a second special, round trips with `<`, `|`, `>` in normal text, and
`ValueError` for a taken id.
