# 8 · Save it, load it, get the same numbers

**The idea.** Training is slow on real data, so a tokenizer is trained once
and saved. Everything else follows from **the merges in order** plus **the
special tokens**; the vocab can be rebuilt. `json` writes dicts, lists,
strings and numbers to a text file. It can't store tuple keys, so store each
merge as a list `[a, b, new_id]` (a list keeps order), and turn the keys
back into tuples when loading.

`with open(path, "w") as f:` opens a file and closes it when the block ends.

```python
import json

scores = {"ana": [3, 5], "bo": [4]}
with open("scores.json", "w") as f:
    json.dump(scores, f)
with open("scores.json") as f:
    back = json.load(f)
print(back == scores)   # True
```

**Your turn.** In `Tokenizer`:
- `save(path)`: write the merges (in order) and the special tokens as JSON
- `load(path)`: replace this tokenizer's merges and specials with the ones
  in the file (merge keys are tuples again) and rebuild `vocab`

**Checked:** save to `tok.json`, load into a tokenizer that was trained on
something else: same merges in the same order, same vocab, identical
`encode` and `decode` on normal text, emoji and `<|endoftext|>`.
