# 4 · Training: repeat until the vocabulary is big enough

**The idea.** Training is a loop of the last two stages. Bytes give you ids
0..255 for free. Each round: count pairs, pick the most common, glue it into
the next id (256, then 257, ...), and remember that rule. `vocab_size` is
how many ids you want in the end, so you do `vocab_size - 256` rounds.

A tokenizer must be **deterministic**: same text, same rules, every time.
So ties need an exact rule. Ours: **highest count wins; on a tie, the pair
that shows up first in the current ids wins.** A dict remembers the order
keys were added, and `get_stats` adds pairs left to right, so a loop that
only replaces the best on a strictly bigger count (`>`, not `>=`) keeps the
first one. Tallest student, first in line wins ties:

```python
heights = {"ana": 170, "bo": 182, "cy": 182}
tallest = None
for name in heights:
    if tallest is None or heights[name] > heights[tallest]:
        tallest = name
print(tallest)   # bo  (cy ties, but bo came first)
```

A small helper for "most common pair" keeps `train` short.

**Your turn.** `train(text, vocab_size)` returns a dict `{pair: new_id}` in
the order the merges were learned.
- `vocab_size < 256` raises `ValueError`
- stop early when there are no pairs left (the ids shrank to one)
