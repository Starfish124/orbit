# 4 · BM25: the ranking search engines actually use

**The idea.** TF-IDF cosine has two weak spots. A word said 8 times counts
8 times as much (no *saturation*), and dividing by the whole vector's
length punishes a long chunk that covers the question well against a tiny
chunk that shares one word. **BM25** fixes both. For each **distinct**
query word `t` found in doc `d`:

    idf(t) = ln(1 + (N - df + 0.5) / (df + 0.5))
    part   = idf(t) * f * (k1 + 1) / (f + k1 * (1 - b + b * len(d) / avgdl))

`f` = how often `t` is in `d`, `len(d)` = its number of tokens, `avgdl` =
the average doc length, `N` and `df` as before. The doc's score is the sum
of its parts. `k1` (1.5) sets how fast repeats stop helping; `b` (0.75)
sets how much length is punished *relative to the average*, not absolutely.

Saturation on a different topic, a stars-per-review cap: the first few
reviews say a lot, the hundredth adds almost nothing.

```python
k1 = 1.5
for f in (1, 2, 8, 100):
    print(f, round(f * (k1 + 1) / (f + k1), 2))   # 1.0 1.43 2.11 2.46
```

It never passes `k1 + 1`: however often a word repeats, its weight is capped.
