# 8 · Hybrid search: words plus meaning, fused by rank

**The idea.** BM25 matches *words*: "canine care" never finds "puppy".
An **embedding model** maps text to a list of floats where similar meanings
land close together, so it finds synonyms, but it is blind to rare exact
tokens it never learned (error codes, product names). Each misses what the
other catches, so real systems run both and fuse.

Their scores are on different scales (BM25 7.3, cosine 0.8), so adding them
is meaningless. **Reciprocal rank fusion** uses only positions:

    rrf(id) = sum over rankings that contain id of 1 / (c + position)

with positions from 1 and `c = 60` (it stops the top spot from dominating).

Your `cosine` already works on dense lists: `dict(enumerate([0.5, 2.0]))`
is `{0: 0.5, 1: 2.0}`, a sparse vector with positions as keys.

Tests give you `embed` from `_fakes.py`: a toy embedder counting words per
topic. Like `llm`, it is injected: swap in a real model without touching
your code. Different job, two judges fused by rank:

```python
judge_a = ["mia", "raj"]            # best first
judge_b = ["raj", "leo"]
# mia 1/61, raj 1/62 + 1/61, leo 1/62  -> raj wins: both judges like him
```

**Your turn.**
- `rrf(rankings, c=60)`: `rankings` is a list of id lists; returns `{id: score}`
- `Index(size=100, overlap=20, embed=None)`: when `embed` is given,
  `add_documents` also stores each chunk's embedding
- `Index.dense_search(query, k=3)`: `top_k` of the cosine between the
  query's embedding and each chunk's; no `embed`: `ValueError`
- `Index.hybrid_search(query, k=3)`: take **every** hit from `search` and
  from `dense_search` (k = number of chunks), fuse the two id lists with
  `rrf`, return `top_k` of that

**Checked:** exact rrf values, dense search finds synonyms and misses codes,
and on a labeled set hybrid beats BM25 and dense alone on MRR.
