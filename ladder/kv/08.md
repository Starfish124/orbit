# 8 · Keys that expire (time as an ingredient)

**The idea.** New requirement: `put(key, value, ttl=10)` means the key
disappears 10 seconds later. The naive version calls `time.time()` inside
the class, and then the only way to test it is to actually wait.
Interview-grade code takes the clock *as a parameter*, so a test can hand
it a fake one.

```python
import time

class Timer:
    def __init__(self, clock=time.time):   # default: the real clock
        self.clock = clock                  # a function, stored, not called
        self.start = clock()                # () calls it

    def elapsed(self):
        return self.clock() - self.start

fake_now = [100]
t = Timer(clock=lambda: fake_now[0])       # lambda = a tiny unnamed function
fake_now[0] = 107
print(t.elapsed())                         # 7, no waiting
```

A parameter with `=` has a *default*: `put(key, value, ttl=None)` can be
called with two or three arguments.

**Your turn.**
- `KV(clock=time.time)`: store the clock
- `put(key, value, ttl=None)`: with a ttl, the key expires at `clock() + ttl`
- an expired key behaves as missing everywhere: `get` is `None`, not
  counted, not found
- a key expires exactly at its moment (`now >= expiry`), not one tick later
- putting the key again replaces its old expiry; transactions keep working

**Checked:** fake clock, boundary exact, count/find skip expired keys,
re-put without ttl lives forever, rollback still works.
