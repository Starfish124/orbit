# 5 · The requirement changes: make it a class

**The idea.** Interviewers love this move: "now I need *two* separate
stores." Your functions all share one global `db`, so they can't. A *class*
is a blueprint; each object built from it carries its own data.

```python
class Counter:
    def __init__(self):          # runs once, when an object is built
        self.n = 0               # self = this particular object

    def bump(self):              # every method takes self first
        self.n = self.n + 1
        return self.n

a = Counter()
b = Counter()
a.bump(); a.bump()
print(a.n, b.n)                  # 2 0  -- separate data
```

**Your turn.** Write `class KV` whose objects each have their own dict

Move your logic into the class; the old functions can go.

Trap to avoid: a dict created *outside* `__init__` (at class level) is shared
by every object. That is the bug this stage checks for.
