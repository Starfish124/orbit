# 1 · A dataset of cases

**The idea.** You changed a prompt. Is the model better now, or does it
just *feel* better? Without a fixed set of questions with known answers,
you are guessing. That set is an *eval dataset*, and the usual file format
is **JSONL**: one JSON object per line, so a broken line breaks one case,
not the whole file.

A file is read line by line with `open`; `enumerate(f, start=1)` gives you
line numbers the way a human counts them. `json.loads` turns a line into a
dict and raises `json.JSONDecodeError` on garbage. Catch it and raise your
own error that says *where*: a 500-line dataset with "invalid JSON" and no
line number is an afternoon lost.

```python
import json

with open("scores.jsonl") as f:
    for number, line in enumerate(f, start=1):
        try:
            row = json.loads(line)
        except json.JSONDecodeError:
            raise ValueError("line %d: not valid JSON" % number)
        print(number, row["player"], row["points"])
```

**Your turn.** New file `evals.py`. Write `load_cases(path)`:

- keep every field (later cases carry extra fields like `"tags"`)
- raise `ValueError` whose message starts with `"line N: "` when line N:
  - is not valid JSON (message mentions `JSON`)
  - is not a JSON object (e.g. `[1, 2]`; mention `object`)
  - lacks `"id"`, `"input"` or `"expected"` (name the missing field)
  - repeats an id seen earlier (mention `duplicate`)
