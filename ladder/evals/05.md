# 5 · Run it again: flakiness

**The idea.** Models sample: ask twice, get two answers. One run that says
"case 12 passes" means little if it passes 3 times out of 10. So you run
every case `n` times and report two things:

- **pass@1**: the chance one attempt passes = the mean of the per-case
  pass rates
- **flaky cases**: passed *sometimes*. These are where your prompt is
  fragile, and where a single run lies to you in either direction

Counting per key is a dict of counters, started at zero:

```python
rolls = [3, 6, 6, 1, 6]
seen = {}
for r in rolls:
    seen[r] = seen.get(r, 0) + 1
print(seen)                   # {3: 1, 6: 3, 1: 1}
print(seen[6] / len(rolls))   # 0.6
```

Reuse beats copying: you already have `run`, so call it `n` times.

**Your turn.** `run_trials(cases, system, grader, n)` returns a dict:
- `"rates"`: case id → fraction of the `n` runs where it passed
- `"pass_at_1"`: mean of the rates (`0.0` for no cases)
- `"flaky"`: ids whose rate is strictly between 0 and 1, in case order
- `n` below 1 → `ValueError`

**Checked:** n=200 over five fake cases: always right, never right,
alternating, crashes once, and a seeded 70% coin; exact rates, the flaky
list, pass@1 as the mean.
