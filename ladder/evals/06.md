# 6 · Better or worse? Comparing runs

**The idea.** v2 scores 64%, v1 scored 62%. Ship it? The single number
hides what moved: maybe v2 fixed 10 cases and broke 8. Compare **per
case**: a *regression* passed before and fails now, an *improvement* is
the reverse. Then ask whether the difference is real or luck.

The **sign test** answers that. Ignore cases that didn't change. If v2
were no better than v1, each changed case would be a coin flip. How
surprising is our split? With `w` improvements, `l` regressions,
`n = w + l` and `k = min(w, l)`:

    p = min(1, 2 * (C(n,0) + C(n,1) + ... + C(n,k)) / 2**n)      (n = 0 → p = 1)

`C(n, i)` is `math.comb(n, i)`: the ways to pick `i` of `n`. Small `p` =
unlikely to be luck. The usual bar is `p < 0.05`.

```python
import math
# 9 heads out of 10 flips: that fair a coin?
tail = math.comb(10, 0) + math.comb(10, 1)
print(2 * tail / 2 ** 10)     # 0.021484375 -> probably not fair
```
