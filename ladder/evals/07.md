# 7 · Slices: where does it fail?

**The idea.** "82% overall" can hide "0% on questions about dates". Real
datasets tag cases (`"math"`, `"long-input"`, `"dutch"`), and the first
thing an AI engineer looks at is the pass rate **per tag**, worst first.
That turns "the model is bad" into "the model is bad at *this*", which is
something you can fix. A case can have several tags; it counts in each.

Sorting by more than one thing: give `sort` a `key` that returns a tuple.
Tuples compare item by item, so the second item only breaks ties:

```python
players = [("bo", 3), ("ana", 1), ("cy", 3)]
players.sort(key=lambda p: (-p[1], p[0]))   # most points, then by name
print(players)    # [('bo', 3), ('cy', 3), ('ana', 1)]
```

`lambda p: ...` is a one-line function without a name.
