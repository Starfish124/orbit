# 2 · Graders: what does "right" mean?

**The idea.** A model says `"paris."` and the answer key says `"Paris"`.
Right or wrong? That decision is a *grader*: a function
`grader(output, expected)` that returns a pair `(passed, reason)`. The
reason matters: when 40 cases fail, "expected 'Paris', got 'Lyon'" tells
you what to fix; `False` alone tells you nothing.

Different questions need different graders: exact text for ids, loose
text for short answers, keywords for long answers, numbers with a margin
for maths (`0.1 + 0.2` is not exactly `0.3` in floats). A pair comes back
as a *tuple*, and the caller unpacks it:

```python
def check_password(pw):
    if len(pw) < 8:
        return False, "too short: %d characters" % len(pw)
    return True, "ok"

ok, why = check_password("hunter2")
print(ok, why)        # False too short: 7 characters
```

`string.punctuation` (after `import string`) is every punctuation mark;
`" ".join(text.split())` squashes all runs of spaces and newlines into
single spaces.

**Your turn.** Four graders, each returning `(bool, reason_str)`, the reason
never empty:
- `exact(output, expected)`: equal strings; the failing reason shows both
- `normalized(output, expected)`: equal after lowercasing, removing
  punctuation and squashing whitespace
- `contains_all(output, expected)`: `expected` is a list of keywords; pass
  when every one appears in the output, ignoring case; the failing reason
  lists the missing ones
- `numeric(output, expected, tol=0.001)`: `float(output)` within `tol` of
  `float(expected)`; output that isn't a number fails, no crash

**Checked:** each grader on matching and non-matching pairs, reasons that
name what went wrong, `numeric` with a custom `tol` and with junk text.
