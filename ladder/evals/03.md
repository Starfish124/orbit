# 3 · Run the whole set

**The idea.** A *harness* feeds every case to the system under test,
grades each output, and adds it up. The system is just a function
`system(input) -> str` that you are handed; in real life it calls a model,
here the tests hand you fakes. That's *injection* again, like the clock
in unit 1.

One rule makes a harness trustworthy: **one bad case never kills the
run.** Models time out, tools throw. If case 37 of 500 raises, you still
want the other 499 graded, and case 37 recorded as a failure with the
error text. `except Exception as e` catches any ordinary error;
`type(e).__name__` is its class name as text.

```python
def safe_div(a, b):
    try:
        return a / b, "ok"
    except Exception as e:
        return None, "error: %s: %s" % (type(e).__name__, e)

print(safe_div(1, 0))   # (None, 'error: ZeroDivisionError: division by zero')
```

`try / except / else`: the `else:` block runs only when nothing was raised.

**Your turn.** `run(cases, system, grader)` returns a dict:
- `"results"`: one dict per case, in case order, with `"id"`, `"output"`,
  `"pass"` and `"reason"` (from the grader, called as
  `grader(output, case["expected"])`)
- when `system` raises: `"output"` is `None`, `"pass"` is `False`, and
  `"reason"` is `"error: <ExceptionType>: <message>"`
- `"pass_rate"`: passed / number of cases, and `0.0` for no cases

**Checked:** four capitals cases (one crashes) give the right per-case
results and pass_rate 0.5; an empty dataset gives 0.0 instead of a crash.
