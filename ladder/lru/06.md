# 6 · "Now do it without OrderedDict"

**The idea.** This is *the* LRU interview question. Using `OrderedDict` is
correct, and the follow-up is always: *"build what it does yourself."*
The answer is a **doubly linked list** plus a dict:

- each key lives in a small `Node` object that knows the node before it
  (`prev`) and after it (`next`)
- the dict maps key → node, so you find any node in O(1)
- unhooking a node and re-hooking it at the end changes four links: O(1)

```python
class Node:
    def __init__(self, key, value):
        self.key, self.value = key, value
        self.prev = self.next = None

# two dummy "sentinel" nodes mean you never special-case an empty list
head, tail = Node(None, None), Node(None, None)
head.next, tail.prev = tail, head

def add_last(node):                 # hook in just before tail
    node.prev, node.next = tail.prev, tail
    tail.prev.next = node
    tail.prev = node

def unhook(node):                   # the neighbours point past it
    node.prev.next = node.next
    node.next.prev = node.prev
```

Draw it on paper first: boxes and arrows. Every linked-list bug is an arrow
you forgot to move.
