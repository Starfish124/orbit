# 5 · Big-O: fast however full

**The idea.** Your cache works. An interviewer now asks: *"what does `get`
cost when the cache holds a million keys?"* `list.remove(key)` walks the
list from the front until it finds the key, and `list.pop(0)` shifts every
item left. The work grows with the size: that is **O(n)**. A dict lookup
takes the same time at 10 keys or 10 million: **O(1)**.

The fix is to keep the order *inside* something with O(1) moves. Python
ships one, `OrderedDict`: a dict that remembers order and can move a key
to the end or drop the first key without scanning.

```python
from collections import OrderedDict

songs = OrderedDict()
songs["a"] = 1; songs["b"] = 2; songs["c"] = 3
songs.move_to_end("a")          # a is now last:  b, c, a
first = songs.popitem(last=False)   # removes the FIRST: ('b', 2)
print(list(songs))              # ['c', 'a']
```
